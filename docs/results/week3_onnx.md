# Week 3, step 1: IRRA image tower in ONNX INT8

Machine: Linux-6.18.44-fc-v310-x86_64-with-glibc2.39, 2 vCPU (Intel Xeon with AVX-512 VNNI, which runs INT8 dot products natively), 2 threads for every backend. Generated by `scripts/onnx_report.py`.

## Speed of the image tower alone

Real person crops (test case 2), warm-up then repeated runs.

| Backend | Size | Batch 1 p50 / p95 | Batch 32 p50 / p95 | ms per crop (batch 32) | Speed-up (batch 32) |
|---|---:|---:|---:|---:|---:|
| PyTorch FP32 | 345 MB | 163 / 169 ms | 3998 / 4260 ms | 125 | 1.00x |
| ONNX FP32 | 345 MB | 139 / 168 ms | 4027 / 4336 ms | 126 | 0.99x |
| ONNX INT8 | 89 MB | 45 / 54 ms | 1265 / 1481 ms | 40 | 3.16x |

ONNX FP32 is no faster than PyTorch; the gain comes from INT8.

## End-to-end ingest (test case 2, first 240 sampled frames, 2 threads)

| Stage | PyTorch IRRA | ONNX INT8 IRRA |
|---|---:|---:|
| embed:irra | 93.2 s (120 ms/crop) | 29.2 s (38 ms/crop) |
| embed:osnet | 116.1 s (150 ms/crop) | 113.8 s (147 ms/crop) |
| track | 37.1 s | 36.4 s |
| detect | 18.1 s | 20.7 s |
| decode | 1.0 s | 0.9 s |
| **wall time** | **266 s** (0.904 frames/s) | **201 s** (1.194 frames/s) |

Ingest is 1.32x faster with INT8 IRRA. Same observations (2,309) and tracks (15) in both runs: detection and tracking are untouched.
OSNet is now the largest stage, and it is slower on 2 threads than it was on 1 (104 ms per crop in Week 2): see AUDIT.md F28.
